# Дизайн: локальное todo-приложение (этапы 1–3)

Дата: 2026-08-06

## Контекст

Проект начинается с пустой папки. Задача — приложение для личного пользования: список дел с матрицей Эйзенхауэра, работающее на десктопе и на телефоне (iPhone/Android), без бэкенда. В перспективе — установка на устройство, офлайн-режим и ручная синхронизация между устройствами по WebRTC через QR-коды.

Работа разбита на этапы. Этот документ покрывает **этапы 1–3**: по отдельности они не проверяемы, потому что скелет без страницы нельзя открыть, а матрица — это второе представление тех же данных.

| Этап | Содержание                                                     | Где описан         |
| ---- | -------------------------------------------------------------- | ------------------ |
| 1    | Инициализация проекта, зависимости, конфиги, тестовая страница | этот документ      |
| 2    | Главная страница: добавление задачи, плоская таблица, хранение | этот документ      |
| 3    | Страница матрицы Эйзенхауэра                                   | этот документ      |
| 4    | PWA и офлайн                                                   | отдельный спек     |
| 5    | Синхронизация устройств (WebRTC + QR)                          | отдельный спек     |
| 6    | Пересмотр модели данных, горизонты, цели и мечты               | отдельный разговор |

Результат этапов 1–3: работающее локально приложение, в которое можно завести дело и увидеть его в двух представлениях, с сохранением между перезагрузками.

## Технические решения и их обоснование

**Хранилище — IndexedDB, не File System Access API.** Safari не поддерживает `showSaveFilePicker` / `showDirectoryPicker` ни на macOS, ни на iOS — только Chromium. Раз iPhone в списке целевых устройств, файловый доступ как основное хранилище отпадает. Работа с обычными файлами останется на уровне ручного экспорта/импорта бэкапа (`<input type="file">` плюс скачивание блоба) — это работает везде, но в этих этапах не делается.

**Сборщик — Vite 8.** Вышел в марте 2026, перешёл на Rust-бандлер Rolldown вместо esbuild и Rollup, plugin API остался Rollup-совместимым. Альтернативы (Rsbuild, Farm) живые, но для Vue 3 экосистема Vite богаче, и Vuetify заточен под неё.

**UI — Vuetify 4.1.x.** Текущая мажорная версия, требует Vue ^3.5. `vite-plugin-vuetify` 2.1.3 нужен для treeshaking компонентов и доступа к SASS-переменным; его peer-диапазон `vite: ">=5"` включает Vite 8.

**Обёртка над IndexedDB — `idb`.** Тонкий промис-слой над нативным API. Dexie мощнее, но его сильные стороны (индексы, сложные запросы, live-запросы) здесь не нужны: набор данных личного масштаба целиком помещается в память.

## Модель данных

Одна запись — одно дело. Модель сознательно упрощена: реальных данных ещё нет, поэтому она пересматривается на этапе 6 без миграций.

```ts
// src/types/todo.ts
export type TodoPeriod = 'one-time' | 'periodic';

export interface Todo {
	id: string; // crypto.randomUUID()
	title: string;
	note?: string;
	created: string; // ISO 8601, UTC
	period: TodoPeriod;
	important: boolean;
	urgent: boolean;
	done: boolean;
}
```

Решения по полям:

- `id` добавлен не ради будущей синхронизации, а потому что без него не отредактировать и не удалить строку таблицы.
- `created` хранится ISO-строкой, а не объектом `Date`. IndexedDB умеет `Date`, но строка переживает JSON-сериализацию — пригодится и для экспорта, и на этапе 5.
- `period` — строковый литерал из двух значений. Частота («раз в N дней», календарные правила) отложена до этапа 6.
- `done` — просто флаг. Журнала выполнений и автосброса периодических задач нет.
- Тегов и меток нет. Они упоминались в первичном описании, но в набор полей MVP не вошли.

Поле для описания названо `note` (в первичном описании фигурировало имя `text`).

## Архитектура

Слои разделены так, чтобы каждый можно было понять и протестировать отдельно, а этап 5 не потребовал переписывания UI.

```
src/
	types/todo.ts             — Todo, TodoPeriod. Единственный источник правды по форме данных.
	services/storage/
		types.ts                — интерфейс TodoStorage и типизированная ошибка
		indexed-db.ts           — реализация на idb
		in-memory.ts            — реализация для тестов и режима деградации
	stores/todos.ts           — Pinia store
	router/index.ts           — маршруты
	i18n/index.ts             — инстанс, определение и сохранение языка
	i18n/locales/             — en.json, ru.json (предкомпилируются при сборке)
	plugins/vuetify.ts        — темы, иконки, локаль Vuetify
	views/
		TodoListView.vue        — таблица
		MatrixView.vue          — матрица
	components/
		TodoForm.vue            — форма добавления и редактирования
		TodoQuadrant.vue        — один квадрант матрицы
	App.vue                   — каркас, загрузка store, баннер ошибки, snackbar
	main.ts
```

### `TodoStorage` — ключевая граница

```ts
export interface TodoStorage {
	getAll(): Promise<Todo[]>;
	put(todo: Todo): Promise<void>;
	remove(id: string): Promise<void>;
}
```

Store не знает, что под ним IndexedDB. Это даёт две вещи: тесты store без браузерного окружения (через `in-memory.ts`) и возможность подключить другой источник данных на этапе 5, не трогая представления.

### Pinia store `useTodosStore`

Состояние: `items: Todo[]`, `loading: boolean`, `persistent: boolean`, `lastError: string | null`. Действия: `load()`, `add(draft)`, `update(id, patch)`, `toggleDone(id)`, `remove(id)`, `dismissError()`. Геттер `quadrants` разбивает `items` на четыре группы по комбинации `important` и `urgent`.

Поле `lastError` хранит ключ локализации, а не готовый текст: store не должен знать текущий язык.

### Матрица — представление, а не отдельные данные

`MatrixView` читает тот же геттер store, что и список. Соответствие квадрантов:

| important | urgent | Квадрант      |
| --------- | ------ | ------------- |
| да        | да     | сделать       |
| да        | нет    | запланировать |
| нет       | да     | делегировать  |
| нет       | нет    | удалить       |

Названия квадрантов в интерфейсе берутся из файлов i18n, а не задаются строками в компоненте.

### Переиспользование формы

`TodoForm.vue` — единственное место, где описаны поля дела. Его открывают обе страницы: список — для создания и редактирования, матрица — для создания дела сразу с предзаполненными `important` и `urgent` того квадранта, в котором нажали «добавить».

### Локализация: две системы, не одна

Свои строки приложения живут в `src/i18n/locales/*.json` и проходят через vue-i18n. Служебные строки Vuetify — «Записей на странице», подписи сортировки и пагинации — остаются в собственной системе локализации Vuetify, которой передаются готовые словари из `vuetify/locale`. Язык Vuetify следует за языком приложения через watcher в `App.vue`.

Разделение не случайно. Штатный способ — адаптер `vuetify/locale/adapters/vue-i18n`, который заводит строки Vuetify под ключ `$vuetify` в vue-i18n. Но тогда эти строки пришлось бы компилировать во время выполнения, а предкомпиляция сообщений как раз убирает компилятор из сборки. Две системы вместо одной стоят одного watcher'а и снимают конфликт.

### Иконки и размер сборки

Иконки — SVG-пути из `@mdi/js` через набор `vuetify/iconsets/mdi-svg`, а не иконочный шрифт. Шрифт `@mdi/font` тянул 403 КБ woff2 и около 7000 иконок ради нескольких используемых, плюс CSS с классом на каждую иконку. Переход убрал шрифт целиком и сократил CSS с 662 до 338 КБ (гзип: 101 → 48 КБ), добавив около 12 КБ в JS на встроенные пути — включая набор `aliases`, который нужен внутренним компонентам Vuetify (чекбоксы, стрелки сортировки, пагинация).

Сообщения предкомпилируются плагином `@intlify/unplugin-vue-i18n` с `runtimeOnly: true`. Выигрыш скромный — 4,6 КБ (1,3 КБ в гзипе): Rolldown в Vite 8 и без того вырезает компилятор сообщений из сборки. Плагин оставлен ради того, что сообщения не разбираются при старте, но рассчитывать на него как на способ похудеть не стоит.

## Поток данных

При старте `App.vue` один раз вызывает `store.load()` — store читает все записи из IndexedDB в память. Дальше представления рендерятся из массива в памяти. При записи действие store меняет массив и дожидается записи в IndexedDB. Полная копия в памяти оправдана масштабом: сотни записей, не сотни тысяч.

## Обработка ошибок

**IndexedDB недоступна** (приватный режим Safari, отказ в квоте): слой хранения бросает типизированную ошибку, store подставляет `in-memory.ts` и выставляет `error`. Приложение остаётся рабочим, в `App.vue` показывается баннер о том, что данные не сохранятся между сессиями. Пустой белый экран без объяснений недопустим — особенно на телефоне.

**Ошибка записи**: snackbar с текстом ошибки в `App.vue`. Молча терять запись нельзя.

## Соглашения по коду

- Код, имена и комментарии — на английском. На русском только сообщения в `src/i18n/ru.ts`.
- Prettier: `useTabs: true`, `tabWidth: 2`, `singleQuote: true`.
- Порядок секций в SFC: `style`, затем `template`, затем `script`. Включается правилом `vue/block-order` из `eslint-plugin-vue`.
- `<style lang="scss" module>` всегда. В `<script setup>` объект `$style` доступен в шаблоне автоматически. Для стилизации внутренностей компонентов Vuetify внутри CSS-модуля понадобятся `:deep()` и `:global()`.
- `<script setup lang="ts">` всегда.
- ESLint 10, flat config: `typescript-eslint`, `eslint-plugin-vue`, `eslint-config-prettier` (последний гасит конфликты форматирования).

## Тестирование

Vitest, юнит-тесты на:

- store поверх `in-memory.ts` — добавление, обновление, переключение `done`, удаление;
- геттер `quadrants` — все четыре комбинации `important` и `urgent`.

Тесты компонентов и e2e на этих этапах не делаются.

## Проверка результата

1. `npm run dev` — открыть, добавить дело, перезагрузить страницу: дело на месте.
2. Перейти на страницу матрицы: дело в квадранте, соответствующем флагам.
3. Переключить тему — выбор переживает перезагрузку.
4. Переключить язык — интерфейс меняется.
5. `npm run test` — тесты зелёные.
6. `npm run lint` — без ошибок.
7. `npm run build`, затем `npm run preview` — продакшен-сборка открывается.
8. `npm run dev -- --host` — открыть с телефона по локальной сети, проверить читаемость таблицы и матрицы на узком экране.

## Вне области этих этапов

Теги и метки, сроки и дедлайны, горизонты (кратко-, средне- и долгосрочные), цели и мечты, частота повторения, история выполнений, PWA и офлайн, синхронизация устройств, экспорт и импорт файла.

## Принятые допущения

- «Табы, 2 таба» прочитано как `useTabs: true` плюс `tabWidth: 2`: один символ табуляции на уровень, ширина отображения — два знакоместа. Варианта «два таба на уровень отступа» в Prettier нет.
- Языки интерфейса на старте — русский и английский. Начальный выбирается по `navigator.language`, переключатель сохраняет ручной выбор.
