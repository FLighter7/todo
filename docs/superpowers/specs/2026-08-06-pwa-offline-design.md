# Дизайн: PWA и офлайн (этап 4)

Дата: 2026-08-06

## Контекст

Этапы 1–3 дали работающее локально приложение: список дел, матрица Эйзенхауэра, хранение в IndexedDB. Оно открывается как обычная веб-страница.

Этот этап делает его устанавливаемым на устройство и работающим без сети. Причина не в удобстве, а в сохранности данных.

**Safari удаляет данные сайта после семи дней без посещений** — IndexedDB, localStorage и регистрацию сервис-воркера. Для приложения, куда человек записывает свои дела, это означает буквально: не открывал неделю — списка больше нет. У веб-приложений, добавленных на домашний экран с `display: standalone`, отдельный счётчик, и правило на них не распространяется. То есть на iPhone установка — единственный способ доверять хранилищу вообще. Источник: [запись WebKit об изменениях политики хранения](https://webkit.org/blog/14403/updates-to-storage-policy/).

Отсюда следует порядок приоритетов внутри этапа: сначала установка (манифест, иконки, `display: standalone`), потом офлайн, потом всё остальное.

## Что входит в этап

1. Веб-манифест и иконки — приложение можно установить.
2. Сервис-воркер с предзагрузкой всех ресурсов сборки — приложение открывается без сети.
3. Запрос постоянного режима хранилища через `navigator.storage.persist()`.
4. Сборка под GitHub Pages с базовым путём `/todo/`.
5. README с объяснением, где живут данные и когда они пропадают.

Синхронизация устройств, экспорт и импорт файла, уведомления и фоновая синхронизация в этап не входят.

## Технические решения

**Инструмент — `vite-plugin-pwa` 1.3.0.** Его peer-диапазон явно включает Vite 8. Он генерирует манифест, сервис-воркер на Workbox и список предзагружаемых ресурсов из результата сборки, что снимает необходимость поддерживать этот список руками.

**Стратегия кеширования — только предзагрузка, без правил времени выполнения.** У приложения нет бэкенда и нет ни одного сетевого запроса после загрузки: данные лежат в IndexedDB, сообщения локализации вшиты в сборку, иконки — это SVG-пути внутри JS. Поэтому достаточно положить в кеш всё, что выдала сборка, и отдавать `index.html` как запасной вариант для любой навигации (приложение — SPA с History API). Никаких `NetworkFirst`/`StaleWhileRevalidate` не нужно, и добавлять их «на будущее» не следует.

**Обновление — `registerType: 'autoUpdate'`, но с осознанной оговоркой.** Новый воркер забирает управление сам, без диалога. Риск известен: если приложение открыто в момент выкладки новой версии, переход на лениво загружаемую страницу матрицы может обратиться к чанку, которого в новой сборке уже нет. Для приложения, которым пользуется один человек и которое обновляется вручную, вероятность мала, а вариант с диалогом «доступно обновление» требует UI и состояния ради редкого случая. Решение принято в пользу простоты; если проблема проявится, лечится переводом матрицы на статический импорт.

**Постоянное хранилище запрашивается один раз при старте.** `navigator.storage.persist()` возвращает обещание с булевым результатом. Отказ не является ошибкой и не показывается пользователю: браузер вправе отказать, а приложение при этом продолжает работать. Результат логируется только в режиме разработки.

**Базовый путь `/todo/` задаётся в конфиге сборки.** GitHub Pages для репозитория проекта отдаёт сайт по подпути. `vite-plugin-pwa` берёт `base` из конфига Vite и подставляет его в `start_url`, `scope` и пути к иконкам, поэтому вручную это дублировать не нужно.

## Иконки

Нужен один исходник и набор растровых размеров из него.

Исходник — SVG: скруглённый квадрат цвета `#1867C0` (основной цвет темы Vuetify) с белой галочкой. Простая форма выбрана намеренно: иконка должна читаться в 48 пикселях на домашнем экране.

Из него делаются:

| Файл                   | Размер  | Назначение                                            |
| ---------------------- | ------- | ----------------------------------------------------- |
| `pwa-192.png`          | 192×192 | Минимальный размер для установки                      |
| `pwa-512.png`          | 512×512 | Крупные плитки и экран запуска                        |
| `pwa-maskable-512.png` | 512×512 | `purpose: maskable`, рисунок вписан в безопасную зону |
| `apple-touch-icon.png` | 180×180 | iOS, объявляется тегом в `index.html`                 |
| `favicon.svg`          | вектор  | Вкладка браузера                                      |

Маскируемый вариант отличается полями: Android обрезает иконку под форму системы, поэтому значимая часть рисунка должна умещаться в круг диаметром 80% от стороны.

Растеризация делается headless-браузером: SVG открывается на странице нужного размера и снимается скриншот. Это убирает необходимость в нативной зависимости вроде `sharp` ради пяти файлов, которые генерируются один раз и коммитятся в репозиторий.

## Проверка

Ключевой момент: **сервис-воркер требует безопасного контекста, и `localhost` в него входит.** Браузеры считают `http://localhost` и `http://127.0.0.1` доверенными наравне с HTTPS. Поэтому весь этап проверяется локально через `npm run preview`, без деплоя и сертификатов — включая автоматическую проверку в headless Chrome.

С телефоном так не выйдет: адрес вида `http://192.168.1.5` безопасным контекстом не является, воркер там не зарегистрируется. Проверка на телефоне возможна только после деплоя или через HTTPS-туннель.

Что проверяется:

1. Манифест отдаётся и разбирается, в нём есть `name`, `start_url`, `display: standalone` и иконки нужных размеров.
2. Сервис-воркер регистрируется и переходит в состояние `activated`.
3. После активации при выключенной сети приложение открывается и показывает ранее заведённые дела.
4. Обе страницы (список и матрица) доступны офлайн, включая прямое открытие адреса матрицы — работает запасной вариант навигации.
5. `navigator.storage.persist()` вызывается и не роняет приложение при отказе.

## Вне области этапа

Синхронизация устройств, экспорт и импорт резервной копии, push-уведомления, фоновая синхронизация, диалог «доступно обновление», настройка деплоя через GitHub Actions.
